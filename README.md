# Indonesia Travel Log

インドネシア滞在中の一次体験を、スマホで手早く記録するための PWA（ホーム画面に追加して使う Web アプリ）です。仕様書 `indonesia_travel_log_spec_v1.1.md`（版 1.1）に沿って作っています。

- 質問を画面に出したまま録音する音声日記、やること・食べたいものリスト、メモ、写真、支出
- 通信がなくても記録できます（初回の読み込みとログイン・同期を除く）
- 本人の同じアカウントで、複数のスマホと PC のあいだを同期します（Supabase）
- 全データの ZIP バックアップと復元、記事素材（Markdown・CSV・音声・写真）の出力
- 日本語とインドネシア語の通訳（家の PC で文字にして訳し、相手に大きな文字で見せる）

> Android 向けのネイティブアプリ（APK）ではありません。仕様どおり PWA として作っており、Chrome でホーム画面に追加すると、アプリと同じように全画面で起動します。

## 使っている技術

React 19 + TypeScript + Vite / vite-plugin-pwa / Dexie（IndexedDB）/ JSZip / supabase-js。バージョンは `package-lock.json` で固定しています。

```
src/
  app/        画面の切り替え・全体の状態
  components/ 共通の部品
  db/         IndexedDB の定義・型・書込み（outbox 登録を含む）
  features/   画面と機能（daily, diary, checklist, notes, media, expenses, history, settings, export, auth, sync）
  lib/        日付・ID・ハッシュ・画像などの小道具
  tests/      自動テスト
supabase/
  migrations/ SQL（テーブル・RLS・RPC・Storage）
  tests/      SQL の自動テスト（PGlite で本物のマイグレーションを流す）
scripts/      アイコン生成・本番 Supabase の RLS 確認
```

## Supabase の設定

同期を使う場合だけ設定します。

1. [Supabase](https://supabase.com) で新しいプロジェクトを作ります（リージョンは Singapore など近いところ）。**有料プランへの自動移行はしないでください。**
2. SQL Editor で `supabase/migrations/` の SQL を、ファイル名の順に実行します（`…0001_sync.sql` → `…0002_storage.sql` → `…0003_interpret.sql` → `…0004_interpret_worker_grants.sql` → `…0005_inbox.sql`。0003 と 0004 は通訳を使うときだけ必要です）。Supabase CLI を使う場合は `supabase link` のあと `supabase db push` でも適用できます。
3. Authentication → Users →「Add user」で、本人のメールアドレスとパスワードのアカウントを作ります（Auto Confirm にチェック）。
4. Authentication → Sign In / Providers（または Settings）で **「Allow new users to sign up」をオフ** にします。公開した URL から他人が登録できないようにするためです。
5. Project Settings → API Keys から Project URL と Publishable key（なければ anon key）を控えます。
6. このフォルダーに `.env.local` を作り、次のように書きます（`.env.example` を写して値だけ入れます）。

   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxx
   ```

   **service_role キー・secret キー・DB パスワードは、ブラウザにもリポジトリにも絶対に入れないでください。** Publishable key はブラウザに出ても問題ない公開用のキーで、データは RLS で守っています。

7. 本物の Supabase で RLS を確かめるときは、テスト用のアカウントを 2 つ作り（A＝本人役、B＝別人役）、次を実行します。パスワードはファイルに書かず、その場で環境変数として渡してください。

   ```powershell
   $env:SUPABASE_URL='https://xxxx.supabase.co'; $env:SUPABASE_KEY='sb_publishable_xxxx'; $env:A_EMAIL='...'; $env:A_PASSWORD='...'; $env:B_EMAIL='...'; $env:B_PASSWORD='...'; node scripts/rls-check.mjs
   ```

### 容量の目安

次の値は 2026-11-26 時点の仕様書の値です。導入時に公式ページで確認してください。

Supabase Free はファイル 1GB、DB 500MB、1 ファイル 50MB まで。音声 64kbps で 1 日 10 分×30 日なら約 144MB、写真 300 枚×1MB で約 300MB です。写真が多くなりそうなら、設定 →「保存状況・容量」の「容量節約モード」をオンにすると、クラウドには長辺 1600px の圧縮版だけを送り、原本は端末に残します。無料プロジェクトは長く使わないと一時停止されることがあります。

- 料金：https://supabase.com/pricing
- ファイルの上限：https://supabase.com/docs/guides/storage/uploads/file-limits
- 一時停止：https://supabase.com/docs/guides/platform/free-project-pausing

## HTTPS で配信する

スマホのマイクは HTTPS でないと使えません。PC の `http://192.168.x.x` を開くだけでは録音できないので、HTTPS で配信してください。

### GitHub Pages

配信先には GitHub Pages をおすすめします。

1. GitHub に新しいリポジトリを作って、このフォルダーを push します（`.env.local` は `.gitignore` で除外済み）。
2. リポジトリの Settings → Pages → Source を GitHub Actions にします。
3. Settings → Secrets and variables → Actions → Variables に `VITE_SUPABASE_URL` と `VITE_SUPABASE_PUBLISHABLE_KEY` を登録します。
4. `main` に push すると `.github/workflows/deploy.yml` がテスト・ビルド・配信をします。URL は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。

配信する中身はアプリ本体だけで、旅行データは入りません。無料プランの GitHub Pages はリポジトリが公開になります（コードとキーは見えても、データは RLS で守られています）。

## スマホへのインストール（Android）

1. Chrome で配信 URL を開きます。
2. 画面の上に「オフラインで起動する準備ができました」と出るまで待ちます。
3. Chrome のメニュー（︙）→「ホーム画面に追加」（または「アプリをインストール」）。
4. ホーム画面のアイコンから起動し、音声日記で一度録音して、マイクを「許可」にします。
5. 設定 →「保存状況・容量」→「データの永続化を要求する」を押します。

## 端末の追加と同期

- 最初の端末では、設定 →「アカウント・端末」でログインします。ログインすると、そのアカウント専用の保存場所に切り替わり、クラウドの記録を取得します。何もなければ、初期設定の期間で旅行を作ります。
- 2 台目以降の端末や PC では、同じ URL を開き、同じアカウントでログインするだけです。ZIP は要りません。
- ログイン前に「ローカル専用」で記録したものは、自動では送りません。設定 →「アカウント・端末」の「ローカルの記録をアカウントへ移す」で、件数を確かめてから新しい旅行として移します。
- 同期するのは、アプリを開いたとき、画面に戻ったとき、通信が戻ったとき、保存の数秒後、開いている間は 30 秒ごと、そして「今すぐ同期」を押したときです。**アプリを閉じている間は同期しません。**
- 画面上部の行で状態がわかります（「☁ 同期済み」「⏳ 未送信 3件（端末に保存済み）」「! 競合 1件」など）。記録は送信前でも端末に保存済みです。
- 同じ記録を 2 台で別々に直すと「競合」になります。違う欄の変更は自動でまとめ、同じ欄で内容が違うときだけ、どちらを残すか選ぶ画面を出します。選ぶまでは両方の内容を保っています。
- 通信量を抑えたいときは、設定 →「同期」で「テキストだけ自動同期」にし、Wi-Fi のときに「音声・写真も全件送信」を押します。
- 他の端末で録った音声・写真は、再生・表示するときか「この日の素材を端末に保存」「全素材を取得」で取得します。取得していない素材は機内モードでは再生できません。
- ログアウトしても端末のデータは消しません（画面からは隠します）。同じアカウントで再ログインすると続きから使えます。
- 端末をなくしたら、Supabase の管理画面（Authentication → Users）でパスワードを変更し、セッションを無効にしてください。オフラインの端末を遠隔で消すことはできません。

## バックアップと復元

同期はバックアップの代わりになりません（誤って消すと、それも同期されます）。**数日ごとに ZIP を作り、PC やクラウドドライブに退避してください。**

- 作成：設定 →「バックアップ」→ バックアップ ZIP を作成 →「ダウンロード」。ファイル名は `indonesia-log-backup_YYYY-MM-DD_HHmm.zip` です。
- 退避：「Files」（ファイル）アプリの「ダウンロード」フォルダで ZIP を長押しし、「共有」→「ドライブ」で保存します。Android の Chrome は ZIP をアプリから直接共有できないため、この手順にしています。
- この端末にない音声・写真がある場合は、先に取得するかを聞きます。取得しなければ「部分バックアップ」になり、欠けたファイルの一覧が `manifest.json` に入ります。
- 未送信の変更と、未解決の競合で食い違っている両方の内容も ZIP に入ります。ログイン情報は入りません。ZIP は暗号化していないので、安全な場所に保管してください。
- 退避できたら「外部に保存できたことを記録する」を押します（作成とダウンロード開始だけでは、退避が済んだことになりません）。
- 復元：設定 →「復元」で ZIP を選ぶと、まず検証（形式・バージョン・ファイルの有無・サイズ・SHA-256・参照の整合性・不正なパス）をして、件数と容量を表示します。
  - 「復元用の領域に読み込む（推奨）」：今のデータとは別の場所に読み込みます。履歴で件数を見たり、音声を再生したりして確認できます。
  - 「ローカル専用の領域を置き換える」：同期していない領域だけを、1 回のトランザクションで置き換えます。途中で失敗すれば元のままです。
  - 同期中のアカウントの領域を ZIP で上書きする機能はありません。クラウドが壊れたときは、復元用の領域から「クラウドへ新しい旅行として送る」で、新しい旅行 ID に付け替えて送ります。確認が済むまで古い旅行は消さないでください。

## 記事素材の出力

設定 →「記事素材の出力」で、期間・種類（全素材／公開候補のみ）・タグを選んで ZIP を作ります。1 日だけ選べば日別の素材 ZIP になります。

```
article-materials/
  README.md / trip_summary.md
  days/2026-11-29.md
  audio/2026-11-29_q01_01.webm   （日付_質問ID_連番。自由録音は free）
  photos/
  csv/tasks.csv, food_wishlist.csv, food_experiences.csv, expenses.csv, daily_ratings.csv, media_index.csv
```

- CSV は UTF-8（BOM 付き）で、Excel でそのまま開けます。`=` などで始まる値には `'` を付けて、式として動かないようにしています。
- 「公開候補のみ」は公開区分を「公開候補」にした素材だけを入れ、支出と定点観測は入れません。写真は再エンコードして位置情報などのメタデータを落とします。顔や会話内容の匿名化はしません。**公開候補にしただけでは、匿名化や同意が済んだことにはなりません。**
- 帰国後にローカルの Whisper などで文字起こしし、音声と同じ名前の `.txt`（例：`2026-11-29_q01_01.txt`）を置けば、日付と質問を対応づけられます。記事にするときは、記録にない事実を AI に補わせず、「観察」「伝聞」「感想」「要確認」を分けて扱ってください。

## 通訳（家の PC で訳す）

下のタブの「通訳」で、話した日本語をインドネシア語に、インドネシア語を日本語に訳し、相手に見せやすい大きな文字で表示します。

- 話す言語の国旗のボタンを押して話します。日本語は「日本語で話す」（日本の国旗）、インドネシア語は「Bahasa Indonesia」（インドネシアの国旗）です。話し終えて少し黙ると、自動で止まって送ります。文字で入力することもでき、文字のときは日本語かインドネシア語かを家の PC が見分けます。
- 日本語は、スマホの音声認識で文字にしてから家の PC に送るので、訳がすぐ届きます（高速モード）。インドネシア語は録音して、家の PC の Whisper で文字にします。スマホのインドネシア語の聞き取りが働かない端末があるためです。Whisper は国旗のボタンで選んだ言語で文字にします。
- 高速モードでも、音声認識がマイクを使い始めてから録音を始め、音声が録れていれば一緒に送ります。録音が無音だった、または録音のせいで聞き取れなかったことが 2 回続くと、録音はやめます。通訳画面の「録音も試す」で、もう一度試せます。
- 訳が届くと全画面になり、まず聞き取った文を出します。合っていれば「↻ 向かいに見せる」（上下を逆にする）か「→ 隣に見せる」（向きはそのまま）を押します。違っていれば「🎤 言い直す」を押すか、文を直します。
- 聞き取った文と訳は、確かめる画面の「📋 聞き取り」「📋 訳」と、見せる画面の「📋元」「📋訳」でコピーできます。どの AI で訳したか（ChatGPT で翻訳 など）も小さく表示します。全画面はスマホの設定に合わせてダークモードになります。
- 見せる画面には、相手が返事を話すためのマイク、読み上げ、☆ があります。☆ を付けた訳は通訳画面の上の「よく使う」に並び、押すとすぐ見せられます。Android の戻るボタンでは全画面だけを閉じ、履歴に戻ります。
- 家の PC では、まずローカル LLM（Ollama の gemma4:26b）で速い訳を出し、そのあと Claude（Claude Code の Haiku）→ ChatGPT（Codex）→ Gemini（Gemini CLI）の順で、より正確な訳に差し替えます。失敗したものは 10 分間使わずに次へ回します。差し替えは 2 件まで同時に進めるので、前の通訳の差し替えを待たずに次の通訳の速い訳が出ます。ローカル LLM は起動時に読み込み、24 時間はメモリに置いたままにします。どれもサブスクのログインか PC の中で動くので、API の料金はかかりません。
- 同じ文を同じ向きで前に訳していれば、その訳を使い回します（通信も家の PC も要りません）。訳は「✎ 訳を直す」で手で直せ、直した訳は自動翻訳で上書きしません。「↻ 訳し直す」で新しく訳せます（直した訳は履歴に残ります）。状態は「翻訳待ち・翻訳中・翻訳済み・手動修正済み・翻訳失敗」で表示します。
- 音声と訳は、端末・Supabase・家の PC（`AUDIO_DIR`、既定は `ユーザーフォルダ\IndonesiaTravelLog\interpret`）に残ります。
- 家の PC が応答しないときは、「代わりの方法」で Chrome の音声認識と Google 翻訳を使えます（通信が必要です）。送った音声は保存されているので、PC が戻れば自動で訳されます。

### 家の PC の準備

1. Supabase の SQL Editor で `supabase/migrations/20261126000003_interpret.sql` と `…0004_interpret_worker_grants.sql` を、この順に実行します。
2. `worker/.env.example` を `worker/.env` という名前で写し、`SUPABASE_SERVICE_ROLE_KEY` に Supabase の service_role キー（Project Settings → API Keys の secret）を書きます。このキーはこのファイルにだけ置いてください。
3. ターミナルで `claude` を起動して `/login` し、Claude Code にサブスクのアカウントでログインしておきます。Codex も `codex login` でログインしておきます。Gemini も使う場合は、Gemini CLI を入れてログインします。
4. `worker\start_worker.bat` をダブルクリックして起動します。「通訳プログラムを起動しました」と出れば準備完了です。止まっても 10 秒後に起動し直します。
5. 旅行中は PC をスリープさせないでください。タスク スケジューラの「IndonesiaTravelLog Interpret Worker」で、Windows にログインすると自動で起動します。

## 情報の取り込み（未整理ボックス）

X・Instagram・Google マップ・ブラウザなどで見つけた情報を、少ない操作で取り込みます。今日の画面の「📥 未整理ボックス」から開きます。

- 共有メニュー：各アプリの「共有」で「旅ログ」を選ぶと、共有された文章・URL・画像が入った登録画面が開きます。「とりあえず保存」を押せば未整理ボックスに入ります。
- 貼り付け：「📋 貼り付けて取り込む」を押すと、コピーした文章を貼り付けた登録画面が開きます。初めてのときは、クリップボードを読む許可を聞かれます。
- 手入力：「＋ 入力」で文章や URL を入力します。キーボードのマイクで話して入力することもできます。「複数の項目として登録する」にすると、空行ごと（空行がなければ 1 行ずつ）に別々の項目になります。
- 「編集して登録」では、登録先（未整理ボックス・やること・食べたいもの・行きたい場所・記事ネタ）、タイトル、カテゴリ、場所、予定日、優先度、日本語訳、メモを入れて、そのまま登録できます。タイトルが空なら、原文の最初の行か URL から作ります。
- 未整理ボックスでは、新しい順・古い順の並べ替え、登録元での絞り込み、キーワード検索、まとめての選択ができます。選んだ情報はまとめてリストへ変換したり、整理済みやアーカイブにしたり、削除したりできます。
- 1 件を開くと、原文・元の URL・画像を見ながら編集し、リストへ登録できます。「複数の項目に分けて登録する」で、1 件から複数の項目を作れます。
- リストへ変換しても、元の情報は「整理済み」として残ります。変換した項目のメモには原文・訳・URL が入り、項目の画面の「📥 取り込んだ元の情報を見る」から元の情報に戻れます。記事ネタは、分類が「記事ネタ」のメモとして登録します。
- 同じ URL（追跡用の引数などを除いて比べます）や同じ文章がすでにあると、警告を出します。別の目的で登録することもあるので、保存は止めません。同じ共有を 2 回保存しても 1 件になります。
- 共有で受け取った内容は、登録するまで端末に別に保管します。ログイン前やログインが切れているときに受け取っても消えません。登録していない共有は今日の画面と未整理ボックスに表示します。
- 翻訳は手で入れる欄と「Google 翻訳で開く」だけです。AI による抽出・分類・翻訳と、画像の文字の読み取り（OCR）はしません。

### 共有メニューに出すには

1. Supabase の SQL Editor で `supabase/migrations/20261128000005_inbox.sql` を実行します。実行するまで、未整理ボックスの情報は端末に保存したまま送信を待ちます（ほかの記録の同期は止まりません）。
2. スマホでアプリを開き、更新の案内が出たら更新します。
3. 共有メニューに「旅ログ」が出るまで、Chrome がホーム画面のアプリを更新するのを待ちます（1 日ほどかかることがあります）。
4. 出ないときは、先に設定 →「バックアップ」で ZIP を作って退避し、同期が済んでいる（未送信 0 件）ことを確かめてから、ホーム画面のアイコンを長押しして削除し、Chrome で URL を開いて「ホーム画面に追加」をやり直します。アプリの記録は Chrome のサイトのデータに入っていて、通常はアイコンを削除しても消えません。念のため先に退避しておき、Chrome の設定で「サイトのデータを削除」はしないでください。

## WhatsApp の会話から取り込む（PC だけ）

PC に保存した WhatsApp の会話ログ（WhatsApp 保存ツールの `messages.json`）を読み、家の PC のローカル LLM で、旅行に関係する情報を登録の候補として取り出します。登録するのは、候補の一覧で選んだものだけです。

- 手動で起動したときだけ動きます。フォルダの監視、定期的な解析、常駐、Windows の起動時の自動実行はしません。
- 会話ログは読むだけで、変更・移動・削除はしません。保存ツールにも手を加えません。
- 会話の全文と、登録していない候補は PC の中だけに置きます（`%LOCALAPPDATA%\IndonesiaTravelLog\whatsapp`）。クラウドに送るのは、選んで登録した内容だけです。根拠の会話の抜粋は、登録のときに「根拠の会話（抜粋）もクラウドに保存する」に印を付けたときだけ送ります。電話番号だけの相手名は「WhatsApp の相手」に置き換えます。

### 使い方

1. 家の PC で `worker\WhatsApp取り込み.bat` をダブルクリックします。黒い画面に「WhatsApp 取り込みを起動しました」と出れば準備完了です。終わったら、この画面を閉じます。
2. 同じ PC の Chrome でアプリを開き、未整理ボックスの「💬 WhatsApp から（PC）」を押します。Chrome が「ローカル ネットワーク上のデバイスへのアクセス」の許可を求めたら「許可」を押します。スマホからは使えません。
3. 期間（今日・昨日・過去 7 日間・過去 30 日間・過去 90 日間・全期間・日付を指定）を選び、「ログを読み込む」を押します。会話相手の一覧が期間内の件数と未解析の件数つきで出ます。
4. 会話相手と取り出す情報（やること・食べたい料理・飲食店・行きたい場所・観光地・会う約束・日程調整・買い物・お土産・note 記事ネタ・現地調査事項・インドネシア語学習メモ・既存予定の変更・中止）を選び、「解析を開始」を押します。
5. 解析中は、読み込んだファイル数・対象のメッセージ数・解析済みの数・進捗率・経過時間・残り時間の目安・候補の数・重複で除いた数・エラーの数が出ます。「途中で止める」で止められます。止めた時点で解析中だったメッセージは、解析済みにしません。
6. 候補ごとにタイトルと登録先を直し、選んで「選んだ N 件を登録」を押します。「元の会話を見る」で前後の会話を確かめられます。登録先は、やること・食べたいもの・行きたい場所・記事ネタ・未整理ボックス・既存の項目に追記、から選べます。不要な候補は「却下」、あとで決めるものは「保留」にします。

カテゴリごとの初期の登録先は次のとおりです。飲食店・行きたい場所・観光地は「行きたい場所」、食べたい料理は「食べたいもの」、note 記事ネタは「記事ネタ」（メモ）、インドネシア語学習メモと既存予定の変更・中止は「未整理ボックス」、それ以外は「やること」です。既存の項目と名前が似ている候補には「似た項目があります」と出ます。

### 再解析と重複

- 「解析済みのメッセージは除く」にしておくと、前回までに解析したメッセージは解析しません。新しいメッセージと、ログが作り直されて本文が変わったメッセージだけを解析します。前後の文脈には解析済みのメッセージも使います。
- 解析に失敗したメッセージは解析済みにしないので、もう一度「解析を開始」を押せば失敗分だけを解析し直せます。
- 「強制再解析」は解析済みのメッセージも含めて解析し直します。同じメッセージから同じ候補は作りません。
- 却下した候補は同じ情報からは出し直しません。会話で予定が変更・中止になったときと、双方が合意したときだけ、もう一度出します。

### ログのフォルダと AI の設定

- 画面の「設定（ログのフォルダ・AI のモデル）」で変えられます。フォルダには、保存ツールのフォルダ、アカウントのフォルダ（`ピクチャ\WhatsApp Status Archive\my_whatsapp`）、`chat_logs` のどれを指定してもかまいません。保存ツールのフォルダを指定したときは、その `設定.json` の保存先から `chat_logs` を探します。
- 初期の AI は Ollama の `gemma4:26b` です。RTX 3090 で実際のログを使って比べた結果、止まらずに速く（30〜80 件を 10〜40 秒ほどで）解析でき、インドネシア語の料理名・地名・日付も取り出せたため、これを選びました。`qwen3:30b` は仕事の話を正しく除けましたが、1 回の解析に 8 分かかって時間切れになることがありました。モデルは画面で切り替えられます。
- OpenAI 互換のローカル推論 API（LM Studio など）を使うときは、`%LOCALAPPDATA%\IndonesiaTravelLog\whatsapp\config.json` の `llm` を `{"api": "openai", "base_url": "http://127.0.0.1:1234", "model": "モデル名"}` のように書き換えます。
- 待ち受けるのは `127.0.0.1:8787` だけです。ポートを変えるときは、環境変数 `ITL_WA_PORT` を設定して起動し、アプリの接続先（つながらないときの画面の「接続先を変える」）も同じ値にします。

## 出発前の実機確認（A16・S01〜S15）

自動テストでは確かめられない項目です。出発前に、実機で次の順に確かめてください。

1. Android の Chrome で配信 URL を開き、ホーム画面に追加する。縦画面で横スクロールが出ないこと。
2. 音声日記で 30 秒ほど録音 →「停止して保存」→ 再生できる。追記録音・録り直し・スキップも試す。
3. 録音中に画面を消す／別アプリへ移る／アプリを強制終了してから開き直し、「中断された録音」が出ること、保存済みの録音が残っていることを確かめる。
4. 機内モードにしてアプリを開き直す → 今日・リスト・履歴が開き、メモ・チェック・録音ができる。
5. 機内モードを解除 → 数十秒以内に「☁ 同期済み」になる。
6. 2 台目（または PC）で同じアカウントにログイン → 1 台目のリスト・メモ・音声が見え、音声を再生できる。
7. 2 台を両方オフラインにして、同じ日の同じ質問に録音し、同じ項目のメモを別々に書く → オンラインに戻すと、録音は両方残り、メモは競合の画面が出る。
8. 設定 →「バックアップ」で ZIP を作り、PC の別のブラウザ（または別のプロファイル）で開いたこのアプリの「復元」で読み込み、件数と音声の再生を確かめる。
9. ログアウト → 同じアカウントで再ログインし、記録が戻ること。
10. 設定 →「同期」の登録端末に、両方の端末が出ること。
11. 本物の Supabase で `scripts/rls-check.mjs` を実行し、すべて OK になること。

## 制限事項・未実施のこと

- GitHub Pages での配信と本物の Supabase は稼働しています。Android のスマホからのログイン、通訳、やることリストの取り込みは使って確かめました。**機内モードでの記録と同期の復帰、2 台目の端末との同期と競合、ZIP の別領域への復元、本物の Supabase での `scripts/rls-check.mjs` は未実施です。** 上の「出発前の実機確認」を行ってください。
- オフライン起動は `npm run build` で作ったアプリで、サーバーを止めて再読み込みし、Service Worker から起動することを確かめました。機内モードでの確認はしていません。
- 本物の Supabase の Storage（アップロード・上書き禁止・署名なしの取得拒否）は、自動テストでは模造で確かめています。`scripts/rls-check.mjs` で確認してください。
- 録音の途中のデータ（5 秒ごとに保存）は、中断後に再生できるとは限りません。
- 写真の撮影日時はファイルの日時からの推定です（EXIF は読んでいません）。HEIC など、ブラウザが読めない形式はサムネイルが出ません。
- 墓石（削除の印）と操作の履歴は無期限に残します。
- ZIP は端末のメモリ上で作るため、数百 MB を超えると失敗することがあります。そのときは記事素材の出力で日単位に分けてください。
- Wi-Fi のときだけ送る設定はありません（ブラウザが回線の種類を正確に判定できないため）。
- 日記の音声の文字起こし、AI の下書き、OCR、他人との共有はしません（仕様の対象外）。文字にするのは通訳の音声だけです。
- 通訳で家の PC を使えるのは、PC が起動していて、通訳プログラムが動いているときだけです。Claude Code などのログインが切れると、その翻訳サービスを飛ばして次へ回します。
- 現在地は、ボタンを押したときと、食べたいもの・行きたい場所を「済み」にしたときだけ取得します。チェックのときは、位置情報がすでに許可されている場合だけ取得し、許可を聞く画面は出しません。常に追跡することはしません。座標は記事素材の「公開候補のみ」の出力には入れません。
- 共有メニューからの取り込みは Android の実機では未確認です。開発環境のブラウザで、Service Worker が共有を受け取って保管し、登録画面に渡せることだけを確かめました。
- 共有や添付で取り込んだ画像は、取り込んだ日の写真としても表示されます（公開区分は「未確認」）。
- 追加仕様 v1.2 のうち、OCR、AI による抽出・分類・翻訳、複数候補の一括登録は実装していません。WhatsApp からの取り込みは、v1.3 の手動取り込み（PC）で行います。WhatsApp から共有メニューで共有された文章は、送り元が「その他」として取り込まれます。
- WhatsApp の取り込みは、追加仕様 v1.3 の P0 だけを実装しています。P1（残り時間の精度の改善、履歴の詳しい表示、複数の会話にまたがる情報の統合、却下の履歴を使った抽出の改善、匿名化した候補の端末間の同期）は実装していません。登録していない候補は PC の中だけにあり、スマホでは見られません。
- AI は旅行に関係のない話（仕事の連絡など）を候補にすることがあります。登録は必ず候補を選んで行うので、不要なものは「却下」してください。
